# AG001: Controller to Repository Direct Dependency

| Attribute | Details |
| :--- | :--- |
| **Rule ID** | `AG001` |
| **Name** | Controller to Repository Direct Dependency |
| **Default Severity** | `ERROR` |
| **Category** | Layer Boundary Enforcement |
| **Analysis Engine** | Bytecode Analysis (ArchUnit ASM) + Dependency Graph |
| **Core Classes** | `AG001ControllerToRepositoryRule, ArchUnitClassAnalyzer` |

---

## Executive Summary & Architectural Rationale

Direct access from presentation/web controllers to persistence repositories bypasses the core architectural layers of enterprise Spring Boot applications:
1. **Transaction Boundary Bypass:** Controllers should never manage database transactions. Bypassing the Service layer means transactional boundaries (`@Transactional`), isolation levels, and rollback semantics are missing or improperly placed in web adapters.
2. **Business Validation & Invariant Skips:** Domain validations, business rules, security filtering, and auditing logic typically placed in services are bypassed, allowing raw database queries or direct mutations from web endpoints.
3. **Tight Coupling to Persistence:** Controllers become coupled to database schemas and JPA entity states, preventing reuse across other ingress adapters (CLI, Kafka consumers, batch jobs, WebSocket handlers).

---

## How It Is Implemented

Evaluated during the **Bytecode Analysis Phase** powered by ArchUnit and ASM:
1. **Class Layer Classification (3-Tier Precedence Ladder):**
   - *Tier 1 (Explicit Annotations):* Inspects bytecode annotations for `@RestController`, `@Controller` (assigned `CONTROLLER` layer) and `@Repository` or types assignable to `org.springframework.data.repository.Repository` / `JpaRepository` (assigned `REPOSITORY` layer).
   - *Tier 2 (Configured Packages):* Matches package patterns configured in `archguard.yml` under `packages.controller` and `packages.repository`.
   - *Tier 3 (Naming Conventions):* Matches class name suffixes `*Controller` and `*Repository`/`*Repo`/`*Dao` only if Tiers 1 & 2 did not match.
2. **Dependency Extraction:** ArchUnit scans compiled `.class` files and records direct dependency vectors between classes:
   - Field types (injected or raw fields)
   - Constructor parameter types (including constructor injection and Lombok `@RequiredArgsConstructor`)
   - Method parameter types and return types
   - Direct method invocations (`JavaMethodCall`)
   - Direct constructor instantiations (`JavaConstructorCall`)
3. **Rule Evaluation:** `AG001ControllerToRepositoryRule` filters `context.getDependencies()` where `sourceIsController` is true and `targetIsRepo` is true.
4. **Deduplication & Snippet Extraction:** Multiple references between the same controller and repository are aggregated into a single `Violation` with combined evidence, mapped back to the source `.java` file line number and source snippet.

---

### False Positive (FP) Handling & Mitigations
A false positive occurs when legitimate code is incorrectly flagged as a forbidden controller-to-repository dependency.

1. **Service Layer Intermediation:**
   - When a controller injects a Service (`OrderService`), and that Service injects a Repository (`OrderRepository`), the dependency vector is `Controller -> Service` and `Service -> Repository`. The rule strictly checks direct edges (`sourceIsController && targetIsRepo`), so mediated dependencies are never flagged.
2. **Shared Domain Entities & DTOs:**
   - Controllers commonly reference entity or DTO classes (e.g. `OrderDto`, `User`). Because entity/domain classes are assigned `ENTITY` or `DOMAIN` layers (not `REPOSITORY`), references to models do not trigger AG001.
3. **Layer Classification Precedence (Tiers 1 & 2):**
   - A helper class named `OrderRepositoryHelper` that is actually annotated with `@Service` is classified as `SERVICE` because Tier 1 (explicit Spring stereotypes) overrides Tier 3 (suffix naming conventions).
4. **Intra-Pair Aggregation:**
   - If a controller calls 5 repository methods in one file, only **one** violation is reported for that pair, preventing alert fatigue and inflated violation metrics.
5. **Suppression Mechanisms:**
   - Can be suppressed via `@SuppressArchitecture("AG001")` or `@SuppressWarnings("archguard:AG001")` on the class or method.
   - Can be excluded via `archguard.yml` rule exclusion patterns or committed to `archguard-baseline.json`.

---

### False Negative (FN) Handling & Defense-in-Depth
A false negative occurs when a controller bypasses the service layer to access a repository, but evades detection.

1. **Lombok `@RequiredArgsConstructor` & Constructor Injection:**
   - Naive AST regex scanners only check for `@Autowired` on private fields and miss constructor-injected repositories generated by Lombok. Because ArchUnit inspects compiled bytecode, constructor parameters and synthetic constructors are fully resolved.
2. **Spring Data Interfaces without `@Repository` Annotation:**
   - Spring Data interfaces often omit `@Repository` (e.g. `public interface UserRepository extends JpaRepository<User, Long>`). The classifier uses `isAssignableToRepository(clazz)` to traverse super-interfaces via bytecode reflection, correctly tagging unannotated Spring Data repositories.
3. **Method Return Types & Parameter Injection:**
   - If a controller endpoint accepts a repository as a parameter or returns a repository instance, the rule captures it via `DependencyType.METHOD_PARAM` and `DependencyType.METHOD_RETURN_TYPE`.
4. **Method Invocations via Raw Instantiation:**
   - If a controller directly instantiates `new SqlOrderRepository().findAll()`, bytecode constructor calls (`DependencyType.CONSTRUCTOR_CALL`) and method calls (`DependencyType.METHOD_CALL`) capture the dependency even without field injection.

## Code Examples

### Non-Compliant (Violating Anti-Pattern)

```java
// VIOLATION: Controller directly injects and uses UserRepository
@RestController
@RequestMapping("/api/users")
public class UserController {

    private final UserRepository userRepository; // Direct repository dependency!

    public UserController(UserRepository userRepository) {
        this.userRepository = userRepository;
    }

    @GetMapping("/{id}")
    public User getUser(@PathVariable Long id) {
        return userRepository.findById(id).orElseThrow();
    }
}
```

### Compliant (Refactored Best Practice)

```java
// COMPLIANT: Controller delegates data retrieval and business logic to UserService
@RestController
@RequestMapping("/api/users")
public class UserController {

    private final UserService userService; // Clean layer separation

    public UserController(UserService userService) {
        this.userService = userService;
    }

    @GetMapping("/{id}")
    public UserResponse getUser(@PathVariable Long id) {
        return userService.getUserById(id);
    }
}
```

### Legitimate Edge Cases Handled Without Alerting

```java
// COMPLIANT EDGE CASE: Controller injects a domain service that internally queries the repository
@Service
public class UserService {
    private final UserRepository userRepository; // Permitted: Service -> Repository

    public UserService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }

    public UserResponse getUserById(Long id) {
        return userRepository.findById(id)
                .map(UserResponse::from)
                .orElseThrow(() -> new UserNotFoundException(id));
    }
}
```

## Configuration & Tuning

In `archguard.yml`, you can customize rule severity, exclude specific classes, or adjust thresholds:

```yaml
rules:
  AG001:
    enabled: true
    severity: ERROR # Options: ERROR, WARNING, INFO
    exclude:
      - "**/legacy/**"
      - "**/*Test.java"
```

### In-Code Suppression
You can suppress this rule directly in source code using either standard Java annotations or ArchGuard annotations:

```java
// Suppress on a specific method
@SuppressArchitecture("AG001")
public void myMethod() {
    // ...
}

// Or using standard Java @SuppressWarnings
@SuppressWarnings("archguard:AG001")
public void myMethod() {
    // ...
}
```
